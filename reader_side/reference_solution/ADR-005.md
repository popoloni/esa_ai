# ADR-005: Prefer the direct explanation adapter for the limited alpha

Status: PROPOSED_FOR_HUMAN_ARCHITECTURE_REVIEW
Decision owner: Technical Lead (synthetic scenario)
Contract: SPEC-004/v1; discovery DISC-003/v1; policy BR-001/v1

## Context
The synthetic product owner permitted only an explanation-only alpha. Both prototypes return the same eight protected routing cases. This is design exploration, not product approval or field validation.

## Alternatives
- direct: one presentation adapter importing the existing routing function. Small change surface, clear for the alpha; coupled to the existing function import.
- ports: explicit RoutingPort and ExplanationPresenter. Supports substitution of a fake routing provider but introduces more types and indirection.

## Decision
Propose direct for the limited alpha because the scenario shows a single provider and limited scope. The team must confirm. We have no measured performance or human-comprehension advantage; this is a local preference, not a universal ranking.

## Consequences
Keep the existing routing rule untouched. Retain the ports prototype as a comparison. Monitor review friction and the need for a second provider; revisit this decision if the interface changes. Re-run the shared acceptance contract after any refactor.

## Evidence and limits
Both alternatives pass 8/8 selected synthetic cases. Performance: NOT_MEASURED. Security audit: NOT_PERFORMED. Release: NOT_APPROVED. No tool or live agent is claimed to have accepted this design.
