# Kiro Design-First — documentation-backed illustrative workflow (2026-10-19)

Primary official reference: https://kiro.dev/docs/specs/feature-specs/tech-design-first/

In a disposable copy of the repository, create a Feature Spec with Design-First workflow.
Present the two prototype structures, existing routing contract and design drivers.
Ask for high-level or low-level `design.md` reflecting alternatives and non-functional
constraints. Compare the generated proposed design to the independently versioned
SPEC-004/v1. Kiro derives *proposed* requirements from the selected design;
that direction is useful for feasibility exploration but MUST NOT override the
human-authorized Chapter 4 behavioral contract. Human review is still required.

This adapter is instructions only: Kiro was not launched during CP05.
Capture product version, generated outputs, required edits and approval identity
if completing an actual client trial. Do not call the design 'verified' based
only on the generated description.
