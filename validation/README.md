# Reproduce observations and collect the remaining evidence

This kit turns the remaining review actions into executable observation plans.
The protocols and blank records are supplied. The retained local native-client
journey is documented in [the reader guide](../practice/native_client/README.md);
its actual attempts and limits must be inspected separately from the unfilled
templates. Independent human-reader sessions and other external trials remain
**NOT_RUN** until their own evidence is collected. Local tests, assistant review,
an installed command, and a completed form do not establish human acceptance.

Use one new directory outside the delivered source tree for each trial. Copy the
appropriate JSON template from `records/`, retain the untouched template and
record the edition, archive identity, actual source identities and selected
scope. Do not change protected lab schemas, source pins or prior receipts to
make an external run appear accepted. Unknown values stay `null`; use zero only
for an observed zero with supporting evidence. Preserve failures and subsequent
corrections as distinct attempts.

## Observe one primary named client workflow

The primary tutorial route is the pinned OpenCode 1.19.3 local-model journey in
[`practice/native_client/`](../practice/native_client/README.md). VS Code with
GitHub Copilot is the documented, unobserved editor contrast. One observed
primary route is sufficient for R06.
The contrast can remain explicitly unobserved, with a meaningful documented
difference and no paired-performance claim. Follow the executable collection
recipe in the reader guide; [NATIVE_HOST_COLLECTION.md](NATIVE_HOST_COLLECTION.md)
explains the generic evidence collector. Confirm each
installation that you actually observe,
extension/client version, exposed model identity and effective settings before
starting. A launcher in PATH is insufficient. Recheck dated adapter instructions
against the installed version and retain the exact integration files loaded.

Create a fresh study copy for the primary client from the retained edition.
If you also observe a second client, use a separate copy from that same edition.
For the first bounded repair, use the CP01 preparation command from the
untouched release so any observed routes receive the same deliberate defect. Capture the
full pre-edit scope and initial failing checks before either client edits. Use
the same intent, allowed edit set and stopping condition. Disclose prior access
to worked answers; do not describe a familiar solution as a blind trial.

Retain the actual prompt, tool calls, generated patch, rejected actions,
interventions, failed attempts and independent checks. Use a native skill or delegated worker only if it serves this bounded task.
If you claim such a capability was used, retain its actual invocation, inputs,
loaded procedure or child task, permissions and output. A rule file alone does
not establish invocation. A native capability is not an extra R06 closure
condition, and it grants no authority to change the intent, acceptance oracle
or pending architecture decision.

A reviewer who did not generate the patch must reconstruct the result from
the retained record and inspect the authorized diff. Record whether that
reviewer is human or an assistant. Human acceptance remains pending when only
assistant review occurred. A useful observed workflow need not be a controlled
product benchmark, and its limitations belong beside its result.

## Observe one generated SDD journey and a scoped contrast

Use one installed framework and coding client with the unchanged Treasury intent
and obligations. Spec Kit is the primary artifact journey; OpenSpec can remain a
clearly labeled, unobserved contrast. One observed route is sufficient for R08.
A second observed route is required before claiming a measured paired comparison;
if you run it, use the same input packet in a separate fresh workspace. Follow the
pinned CLI reproduction instructions and retain the actual installed versions.
Do not copy the populated before or after teaching specimens into the
generated-result directories.

Record the exact initial input and the actual model/client prompts through
specification, clarification, and the plan/design and task phases actually reached.
Save the first generated artifacts before repair. Retain every clarification,
omission, correction and regenerated artifact. If the framework stops on an
unanswered question or a failed gate, preserve that actual stop and identify the
downstream phases that did not run. An observed stop is evidence of that phase,
not a passed downstream gate or an invented owner answer. A framework scaffold or
structural validator is one observation; generated domain content and its fidelity
are separate observations.

Keep the owner obligations and review process under independent control. Record
which expected answers were visible to the generating client; a hidden-evaluation
claim requires an actual access arrangement. An independent requirements
reviewer must trace the ambiguity and boundary case through the observed route,
including any task artifacts produced, and assess unresolved questions or stops.
If a second route is observed, review it against the same obligations. Preserve
disagreements and their resolution. Passing the
book's fixed-format checker alone does not establish general natural-language
equivalence or human requirements approval.

## Observe reader navigation and recovery

Recruit readers from the stated experienced-developer audience and record their
relevant background and prior exposure. Give them the final archive and normal
entry instructions. The author should observe before coaching; record each
request for help and any supplied answer. This is a formative usability exercise,
not a delayed-retention study or a validated competence assessment.

Ask each reader to locate the current state, perform a bounded repair, interpret
the CP07 blocked decision, recover after a receipt becomes stale, select the
fresh harness copy, and explain the Chapter 13-to-14 routes. Record completion,
errors, navigation choices and help for each task. Use elapsed time only with
its actual start/end and collection method. Ask the reader to explain why the
route or recovery is valid, rather than accepting a green status as evidence
of understanding.

The ordinary synthetic lab requires no 24-hour wait. A reader can choose the
Chapter 14 worksheets without creating CP13 sessions; the executable lab needs
the matching synthetic chain. If a task exposes a confusion, record it, revise
the relevant instruction, and retain a new observation rather than deleting
the failed one. Agent walkthroughs can help find defects but are recorded
separately and do not close independent human reader acceptance.

Use the chosen repository and immutable release identity after the author and

upstream runtime skips explicitly. Only list an environment as observed when its
matching receipt exists. This record concerns release support, not publisher
acceptance of the manuscript.

## Verify one MCP coding host and its effective boundaries

Choose a named host and use the same read-only policy lookup in
`../practice/mcp_cli/`. Retain the opening exchange appropriate to the observed protocol era, tool
discovery, a valid result,
the unknown-policy refusal, a schema-invalid call and shutdown/error evidence.
Record the actual transport and selected protocol. Legacy 2025-11-25 uses
initialization; modern 2026-07-28 uses discovery and per-request version metadata.
Do not require an initialization request from a modern trace. Compare semantic results
with the CLI without treating serialized bytes as tokens or charges.

Audit effective process permissions separately. Declare the permitted files,
environment-variable names and network destinations, then use a disposable test
workspace and non-secret canaries to compare expected and observed behavior.
Retain effective OS/container/host settings and the observation method. Never
put credential values into evidence. Do not widen permissions silently to turn
a timeout into success. An application refusing a path-like policy identifier
does not establish that its process cannot read unrelated files or open a
network connection. Mark any untested boundary `NOT_TESTED`.

## Collect team outcomes and costs

Use the existing field worksheet and copy
`../reader_side/measurement/FIELD_TELEMETRY_TEMPLATE.json` to the new observation
directory. Its schema and protocol remain authoritative for the collection;
the index record here points to the actual copied data and receipts. Do not
duplicate or relax that schema to fit a convenient result.

Declare the task-selection rule, comparison, cutoff, accepting role and cost
allocation before collecting outcomes. Retain all attempts, review/rework,
attributable effort, applicable bills, accepted outcomes and missing records.
Reconcile overlapping person-time and shared charges before totals. Distinguish
actual charges from assumed-rate estimates. Missing inputs remain unknown;
zero accepted outcomes makes a per-accepted-outcome ratio undefined.

Record a bounded continue/change/stop recommendation with the actual owner
decision. The practical agreement and dashboard are already supplied teaching
materials. Field observations support only the claims their design permits;
they do not by themselves establish causal productivity or learning gains.

## Optional model-backed harness study

Run this only if the book is to make a claim beyond the existing deterministic
lesson. Declare the task sample, fixed executor model, editor model, versions,
baseline harness, total refinement budget and stopping rule before testing.
Separate improvement inputs from evaluation information and record the actual
filesystem/network boundary and any exposure of public grading material.

Retain the original baseline, all probes including failures, composed candidates,
selection decisions, independent evaluation and actual costs. A later reuse
claim needs separately recorded later tasks and source dependencies. Report
the study's sample and limitations; do not inherit the deterministic fixture
scores or the paper's benchmark results. This optional study is not a missing
implementation requirement for the delivered local teaching exercise.

## Close an action from evidence

Each record has a separate acceptance decision, reviewer identity and evidence
list. Complete those only after checking the original criterion, not merely
because a command completed or a record exists. Link completed records back to
the action register, preserve their earlier versions, and state which claims
are now supported and which remain open.
