# G1/I01 — first durable reservation (synthetic slice contract)

Status: initial teaching brief, G1/I01-draft, 2025-05-14. Owner: fictional workshop coordinator.
Read the brief, record your open questions, then request the owner response before implementation. The brief intentionally leaves a decision open; the eventual tests do not supply a secret requirement.
This document governs G1. `RES-001/v1` in `docs/contract.md` is the final contract;
its validation, overlap, replay and concurrency rules are the G2 backlog.

## Public interface

- `init_db(path: str | Path) -> None` creates local SQLite storage if needed and preserves existing data.
- `reserve(path, *, trusted_member_id, asset_id, starts_at, ends_at, idempotency_key) -> Outcome`
  accepts one valid first request in an empty database. All request fields are strings;
  identifiers are nonempty, at most 128 characters and may contain quotes. The caller
  already supplies trusted identity and canonical UTC timestamps. The interval is
  positive and no longer than 24 hours.
- `Outcome` is a dataclass with `status`, `code`, `reservation_id`, `replayed`.
  A successful first call returns `201`, `confirmed`, a positive integer identifier,
  and `False`. These numeric codes are teaching outcomes; no HTTP service exists.
- `get_reservation(path, reservation_id: int)` returns a fresh mapping
  with exactly `reservation_id`, `trusted_member_id`, `asset_id`, `starts_at`,
  `ends_at`, `idempotency_key`. Values must equal the original request and returned
  identifier, for a reservation that exists. Reading does not modify records.

Confirmation means the row has been committed before `reserve` returns. A new
process must retrieve it through `get_reservation`; in-memory state is insufficient.
Data values must be bound safely to SQL. Unexpected storage failures propagate;
they are not successful business outcomes. Table names and column names are private.
No request fingerprint or `request_hash` is required for this slice.

## Acceptance example to derive before implementation

Given an empty database, member `member-1`, asset `A`, interval
`2025-05-14T09:00:00Z` to `2025-05-14T10:00:00Z`, and key `key-1`, when the member
reserves, then the result is `201/confirmed` with a positive identifier and no replay.
When another process reads that identifier, all six public fields match the request.

in `QUESTIONS.md`. The `clarify` step supplies a dated owner response and then

The public acceptance suite has four methods. The separate-process probe is an
additional observation; it is not counted as a fifth test or as crash recovery.

## Deferred design decisions

G2 introduces strict input validation, overlap/adjacency, replay and changed-key
handling, fingerprinting and schema migration, and an atomic check-and-insert.
Canonical timestamps make lexical ordering meaningful. Two concurrent writers
need `BEGIN IMMEDIATE` or an equivalent protected transaction. G1 establishes
neither behavior; leave the full-contract diagnostic visible.
