**Acceptance example**
- member-1 reserves A 09:00–10:00, which gives id 1 at version 1.
- `cancel(1, expected_version=1)` returns 200/cancelled at version 2.
- Repeating with version 2 returns 200/already-cancelled at version 2.
- Repeating with the old version 1 returns 409/stale-version.
- member-2 can then reserve the same slot and gets 201.
- Replaying member-1's original request returns id 1 with `replayed=True`, and the row stays cancelled.

**What changed in `booking.py`**
- The schema is now version 3. `reservations_v2` gains `state` (`active` or `cancelled`) and `version` (default 1).
- `init_db` migrates a G2 (version 2) database to version 3 in one transaction. IDs and the six public fields are unchanged.
- `reserve` only treats active rows as blocking an interval. The replay lookup ignores state, so a replay returns the original identity and never revives the row.
- `reservation_status` is a read-only lookup that returns `{state, version}` or `None`.
- `cancel` does its check and update in one `BEGIN IMMEDIATE` transaction.
- `get_reservation` is unchanged.
