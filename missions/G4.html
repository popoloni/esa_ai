G4. Diagnose first, then account for the decision

Run commands from the package root. Live-client setup and current status · Offline recorded tours

Session planning target: setup 10 min · implementation 25 min · review and handoff 20 min (55 min total).

An operator reports that two active reservations overlap. A proposed repair would remove one row immediately. Another proposal claims a low cost per outcome by dividing effort by every attempted diagnosis. Before changing either data or the business case, establish what the evidence actually says.

Your deliverable combines working diagnostic code with an analytical handoff. You must observe existing state without changing it, distinguish diagnosis from repair authority, and count the total effort required to obtain an accepted outcome. All databases and cost inputs in this mission are identified teaching fixtures; they do not describe a production incident or measured team productivity.

OPS-G4/v3 names three exact schema-3 mappings: the supplied reference reservations representation and two retained reservations_v2 layouts. Match their complete documented signatures; preserved historical tables are not current reservations. Refuse unsupported or competing mappings. Schema version alone does not authorize a guess or change G1’s public acceptance contract.

Your own G3 may keep its reservations in another table. In that case advance issues the owner mapping G4-OD-01 for your lineage alone, in docs/G4-OD-01.md and docs/G4-SCHEMA-MAP.json, when every column uses a name that the named layouts already give to the same role. Read it before delegating: it adds one current representation and keeps every refusal. If no mapping follows from the names, advance refuses and shows how to supply one with --schema-map, acting for the owner.

diagnose(path) must read an existing database, report its resolved path, schema version, state counts and overlapping active pairs, and record a digest. It must exclude adjacency and cancelled reservations. It must not initialize missing storage, delete a reservation or quietly repair an inconsistency. If bytes change during the observation, it must refuse to claim a stable result.

Write two hypotheses before delegating: an actual active overlap and a false alarm caused by counting a cancelled row. Specify the observation that separates them. Then name who may authorize a correction. A diagnostic implementation can identify two rows without determining which reservation should take precedence.

2. Delegate: retain evidence and count all attempts

The second function is cost_summary(attempts, accepted). Each attempt supplies cost_eur and minutes. Include failed generations, debugging, review and recovery when those costs belong to the comparison. Sum finite, nonnegative values with Decimal arithmetic. Nonnumeric, nonfinite and negative cost or time must raise ValueError, so malformed text has the same public failure category as other invalid numeric values. The number of accepted outcomes is a separately supplied decision count. It is not the number of attempts and is not inferred from tests.

For example, the continuation uses three illustrative attempts costing EUR 3.40, EUR 0.60 and EUR 1.50, with 12, 7 and 18 minutes. If one outcome is accepted, the account includes all EUR 5.50 and all 37 minutes. Those inputs are scenario values, not measurements from a real reader or model session. A different experiment must supply its own observed costs and an explicit acceptance rule.

When no outcome has been accepted, unit cost and unit time are unavailable. Return null for those metrics and status NO_ACCEPTED_OUTCOME. Returning zero would make an unsuccessful experiment appear maximally efficient; dividing by zero would discard the useful total-cost observation.

Continuation observes a clean fixture, introduces labeled corruption, then runs your diagnostic without repair. It retains incident_fixture.sqlite, diagnosis.json and cost_report.json under work/evidence/g4-handoff/. The actual AP-G4 handoff found ACTIVE_OVERLAP with unchanged evidence and repair_authorized=False; its independent receipt retained the candidate. The EUR 5.50/37-minute cost inputs remain illustrative, not coding-agent costs.

Complete two short sections in DOSSIER.md. The operational section names the selected state, observed overlap, unchanged evidence, supported hypothesis, remaining uncertainty and owner of the repair decision. The economic section states the cost boundary, all included attempts, accepted-outcome definition, totals, denominator and next experiment. Keep a proposed repair separate from an executed repair; the latter has not occurred in this mission.

Suppose another diagnostic run would cost ten minutes and EUR 0.80. Explain what new information would justify it. Repeating the same query against unchanged state supplies little additional evidence; checking a different hypothesis might change the decision. This is an analytical judgment, not a required fabricated measurement. Record your assumptions clearly.

Explain the decision

Why is a read-only connection useful even when you intend to run only SELECTs? What would a changed before/after digest invalidate? Why must cancelled rows be excluded from the overlap diagnosis? How does an accepted-outcome denominator differ from an attempts denominator? What remains meaningful when accepted is zero? State exactly which owner decision would be necessary before deleting one of the incident fixture’s rows.
