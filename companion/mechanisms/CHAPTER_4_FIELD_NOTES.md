## Follow a claim through the B1 memory lab

From the directory containing `companion/`, run the example in a fresh output directory:

```bash
python3 companion/memory/demo.py --output work/memory-b1
```

Open `work/memory-b1/RESULTS.json` and `events.jsonl`. The task is `B1-grammar-check` on `treasury.routing.assess`. The input API version, result fields, cited source and observed candidate identify the scope. The local grant file checks declared authority. It does not authenticate a real policy owner. The full procedure and field descriptions are in `companion/memory/README.md`.

| Question to answer before opening the result | Evidence to inspect afterward |
| --- | --- |
| Can the worker reuse the v1 exponent-notation claim on v1? | Its source and evidence digest, applicability, validity and promotion decision. |
| What should a v2 lookup return for that same claim? | Its exclusion from current guidance and the preserved historical v1 record. |
| What happens after a source change or expiry? | The reason for revalidation and the identity of the affected claim. |
| A v2 card forbids a leading plus. What could disprove it? | The approved API and the result for `+4999.99`. The false card is a constructed control. |
| Can a corrected claim become active? | A distinct version, an independent promotion decision and a link to the contradiction. |
| Can a secret marker or a request for extra permissions enter trusted memory? | The refusal for the synthetic fixture and the contents actually retained. |

Give a second worker only the admitted records, the current contract and the candidate identity. Ask which claim is applicable, which result belongs to the old version and what still needs checking. Record what the worker actually retrieved and which fact changed its next action. The memory ledger tests record handling; a learner's ability to reconstruct the reasoning requires a separate observation of that learner.
