Native run of all eight missions, 16 November 2026

All eight missions and all twelve required stages of NATIVE_SESSION_MATRIX.json completed through agent_session.py with a native coding client, and every mission’s printed protected check and continuation passed on the candidate the agent produced. native_ledger.py reports verified_native_missions: 8.

The operator was an AI. Claude (model claude-opus-5-5), working in the author’s review session, wrote the operator questions, launched each run, read the events, ran the protected checks and its own probes, and recorded every decision with --operator-kind AI. No human operated, steered or accepted a mission. This run closes the native-route gap; it does not close the human-operator gap.

What the operator had to decide

G1, question stage. The worker stopped without implementing and asked what get_reservation returns for an absent identifier, the same gap the operator had written down. Only then was the supplied owner response released.

G2, the worker refused its own predecessor. The native G1 stores g1_reservation(id, …), which no G2 decision authorizes. The worker migrated the three authorized representations and refused its own lineage’s table with “owner mapping required”, leaving the bytes unchanged. That is the contracted behaviour. The checks do not exercise it, because the continuation migrates the reference representation; the operator probed it separately.

G3, an operator error. The first G3 run blocked: every protected method failed in setUp because the test fixture builds the reference G2 layout, which the candidate refused. Part V says the AP-G3 task required both the retained G2 schema and the supplied fixture; the operator’s task had omitted that. A bounded follow-up with the printed AP-G3 wording passed. The failed receipts are retained.

G3 integration, a checker defect. Both role checks passed, but the first combination blocked: verify_transport.py required cancel() to equal the reference dictionary {status, code, version} exactly, and the native candidate also returns reservation_id. Neither RES-002/v1 nor INTEGRATION-G3/v1 fixes the key set, and the protected G3 tests read only those three fields. The checker was narrowed to the contracted fields; the resumed combination passed nine of nine cases on the extracted package. The blocked receipt is retained.

G4, ASK and a contract extension. OPS-G4/v2 recognised only the reference and the AP-recorded schema-3 tables and said it “does not certify an arbitrary schema3 database”. The worker implemented diagnose and cost_summary, then stopped because the native G3 table matches neither (8 of 11 methods). Following the precedent of G2-OD-02 and OPS-G4/v2, both authored by the AI recording operator under the author’s instruction, the operator authored OPS-G4/v3, adding the native signature. G4 was re-advanced from the same accepted G3 integration with the worker’s two files carried over unchanged (hashes in work/notes/g4-carry-02.txt), and a fresh session passed.

Instruction versus enforcement

The client denied 25 operations across the fifteen launches, all reported in the final permission_denials field: compound commands, environment-variable prefixes, heredoc writes, and one Write to the package root outside the candidate. Each time the worker found an allowed route and said so. Three observations matter for Chapter 4:

  • Claude Code gives each session a scratchpad directory outside the candidate and permits writes there. Several workers wrote probe scripts in it, contrary to the literal task wording. The candidate snapshot does not cover that directory.
  • In acceptEdits mode the client also approved rm -rf __pycache__ inside the CLI worktree without a denial.
  • Workers ran read-only git status in parent directories and reported the operator’s own uncommitted adapter edits in this package.

Open owner questions

  1. G2: may records written by the native G1 representation g1_reservation be mapped column for column, like G2-OD-02? Nothing was invented; migration refuses them.
  2. B3: does “retains the legacy table unchanged” cover only rows, or also the triggers the supplied migration adds?
  3. OPS-G4/v3 is an AI-authored teaching-case extension and needs the author’s review. It still cannot certify any other learner schema; a general mapping step would remove the problem for every lineage.

What this run does not establish

  • Human operation, human acceptance, usability or learning: no person took part.
