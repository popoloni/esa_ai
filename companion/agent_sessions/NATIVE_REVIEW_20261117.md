## The additional G4 regression

OPS-G4/v3 requires refusal when two recognized current representations compete. The retained native implementation did not refuse two such combinations. The original eleven-method suite missed these cases. The current protected suite has thirteen methods, including both discriminating regressions. The original candidate and its historical receipt remain unchanged; a separately labelled correction and fresh receipts are retained under `evidence/g4_native_audit_20261117/`.

The correction was made by the present audit operator. It is not a new Claude Code execution, and no human acceptance is inferred. Historical recorded episodes keep their original contract versions and test counts.

## Codex validation and the remaining live gate

The adapter has separate protocol validation and coverage selection for Codex and Claude. Constructed transport controls verify argument handling, immutable capture and rejection of the wrong client's event stream. A Codex-only collection cannot count Claude sessions as Codex results. These controls do not call a model.

A real B1/v1 Codex launch was attempted with the installed `0.167.0-alpha.4` client and its existing configuration. The client exited before emitting any event: `failed to initialize in-process app-server client: Read-only file system (os error 30)`. No candidate file changed. A minimal direct-client control from an empty directory failed at the same startup point without receiving companion content. Native Codex coverage therefore remains zero of eight missions and zero of twelve stages in this release. The exact B1 task, invocation, snapshots and result are retained under `evidence/native_codex_20261117/`.

Use a functioning, authenticated Codex installation to complete the live gate with the quickstart. Do not infer successful native execution from installation inspection or the synthetic controls. Human-operated sessions and reader pilots are separate evidence requirements.
