Current acceptance scopes

G1 slice (compatibility alias first) runs four public-API methods after the supplied G1-OD-01 owner response. all remains slice4 + final_api10. readonly runs two public checks of absent paths and URI-special names; continuation runs slice4 + readonly2, then an explicitly separate two-process persistence probe. The adapted final ten do not assume internal tables. The archived original ten are selected only by archived (legacy alias historical) and retain their original schema dependency. They are not the current handoff gate.

B1 core selects seven unchanged original numeric methods, extended five public finite/type methods, and all both. A B1-API/v2 working copy adds six version-specific grammar methods to all. The legacy selection historical continues to mean core for B1, but new receipts use the current name.

The public precision probes use two v1 inputs against all three current B1 proposals. They expose the binary-float false green and pass on the positive control. Those inputs are not silently reused under the narrower v2 grammar. The process-boundary G1 probe rejects a registry that loses data when its writer exits; its local slice checks still pass. These are constructed teaching cases, not model performance or human learning measurements.

The earlier dependency-specific failure probes remain available with archived candidate packs. They are separate from public acceptance and must be adapted before a claim can be made about a differently structured implementation.

Later missions

The single entry point dispatches G2–G4 and B2–B4 using curriculum/MANIFEST.json. G2 runs fifteen methods; G3 seven; G4 seven; B2 eight; B3 ten; B4 six. Protected tests, contracts, carried dependencies and prior snapshots are hashed before execution. Each continue adds an executed offline fixture and preserves its files beside the receipt. The method counts do not include these demonstration observations.

G2’s named migration fixtures are schema-aware by explicit owner decision; G3 adds schema version 3 while preserving the old public lookup. G4 is deliberately an operations adapter for that identified schema. B3 keeps HISTORY-API, storage schema and business-policy versions distinct. B4 diagnosis is read-only and its restoration example changes a local JSON binding, with probes on a disposable copy and original ledgers preserved.

The eighteen later proposals are constructed and use neutral IDs. Each mission has a valid current implementation, a contract-violating change and a request for new owner authority. Check success alone cannot answer the last proposal’s policy question. verify_curriculum.py records positive and negative controls, exact commands and source hashes without inferring human learning or model performance.
