B2 proposal cards

B2-P01

The batch loop tries to finish an item already in progress after a transient provider interruption. It preserves the request identifier and records every invocation so the caller can see the effort spent before the batch returns. The completion path is designed to avoid abandoning useful work at the edge of an allowance. Review that path against both the item-level and batch-level budgets.

Artifact: evaluate_batch: the budget guard before the next provider invocation.

if len(attempts) > max_calls:
    break
event = {"request_id": key, "attempt": attempt}
attempts.append(event)

B2-P02

A classification is usable only when its response belongs to the submitted request and has the agreed shape. The adapter checks that relationship before adding a completed record. It distinguishes the retryable provider condition from other failures and retains the attempt evidence on exceptions. Invocation bounds and response validity remain separate decisions in the loop.

Artifact: evaluate_batch: response validation after recording the current attempt; exceptions retain the receipt.

if (

B2-P03

Duplicate detection belongs before the first provider effect. This proposal examines the entire submitted batch before entering the existing bounded loop, so a late duplicate cannot invalidate work after calls have already occurred. It addresses identity within this batch only. A later process retry still needs the durable identity contract introduced in the history mission.

Artifact: Preflight helper called before the provider loop; error snapshots are attached by evaluate_batch.

def _unique_requests(requests):
    rows = list(requests)
    ids = [row["request_id"] for row in rows]
    if len(ids) != len(set(ids)):
        raise ValueError("duplicate request_id in this batch")
    return rows
requests = _unique_requests(requests)
